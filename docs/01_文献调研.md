# 暴雨洪涝快速仿真与 LLM 决策：文献调研

调研日期：2026-07-27

## 1. 调研问题

本轮围绕五个问题展开：

1. 元胞自动机能否在城市强降雨场景中实现快速且可验证的二维积水预测？
2. 如何表示降雨、入渗、地表汇流、微地形和排水管网？
3. 如何把实时雨量、雷达、积水点等观测纳入滚动预测和不确定性表达？
4. 如何从“水深图”转化为面向道路、建筑、人口和关键设施的影响评估？
5. LLM 在灾害决策中适合做什么、不适合做什么，如何限制错误传播？

## 2. 研究谱系

### 2.1 高精度水动力与快速模型

完整或简化浅水方程模型具有较强物理解释力，但在高分辨率城市地形、大范围集合预报和分钟级更新中计算成本较高。2021 年的城市地表洪涝模型综述将水动力、CA、数据驱动等路线并列讨论，指出 CA 在快速淹没模拟方面有前景，但精度依赖地形、参数、边界和模型简化条件 [L1]。

因此，本项目不把“CA 一定优于水动力模型”作为前提，而采用两层策略：

- CA 是实时主模型；
- 高保真水动力模型和实测事件是离线校准、误差审计与适用边界判定的基准。

### 2.2 WCA2D/CADDIES：水深与快速演化基线，但速度矢量需谨慎

Guidolin 等提出的 WCA2D 使用水面高程差与权重规则在相邻格点间分配水量，以较简单的转移规则替代完整浅水方程，并天然适合 CPU/GPU 并行。论文在解析算例和多个案例中与物理模型比较，强调了速度和内存优势 [L2]。

其适合作为快速基线的原因是：

- 保留时间步，可输出水深随时间变化、到达时间和持续时间；
- 栅格结构便于与 DEM、建筑、道路和降雨雷达对齐；
- 局部邻域更新便于 GPU 并行；
- 可通过源汇项加入降雨、入渗、排水和边界交换。

但用户明确把水深、流速和方向都列为一级灾害要素后，WCA2D 不宜直接作为唯一主模型。采用水位差分配、忽略或弱化动量守恒的扩散波式 CA，在速度矢量和结构入射角方面存在先天弱点 [L15]。其速度优势也不能直接外推到本项目；区域大小、分辨率、湿单元比例、时间步、GPU 型号和耦合方式都会改变性能。

### 2.3 动态波 CA（SWFCA）：更新后的主求解器候选

Chang 等提出的动态波 CA 框架（SWFCA）使用伯努利水头联系水深与速度，显式表示质量与惯性的传播，并以规则流和强间断流算例进行验证 [L16]。这类模型仍保留局部元胞更新和并行潜力，但比“只按水位差摊水”的 CA 更适合输出：

- 水深 $h$；
- 两个方向的单宽流量 $q_x,q_y$；
- 深度平均速度 $u=q_x/h,\ v=q_y/h$；
- 速度模长和方向角；
- 与建筑表面法向相关的冲击分量。

因此更新后的路线是：**SWFCA/混合动态波 CA 为主求解器候选，完整浅水方程有限体积模型为离线基准，WCA2D 为快速对照，CA-ffé 为最终淹没筛查。**

### 2.4 CA-ffé：适合作为超快筛查基线，不宜单独承担实时演化

CA-ffé 只依赖地形和连续性思想，不显式使用建模时间步，可在社区尺度快速给出最终淹没范围和水深 [L3]。论文同时明确指出：在高动量、高流速区域深度估计较弱，且不能表示洪水时间演化和流速 [L3]。

由此得到一个直接设计结论：

- CA-ffé 可用于大批情景预筛、最坏情景搜索或计算降级模式；
- 需要到达时间、路段封闭时刻和滚动预警时，必须使用带时间演化的 CA 或水动力模型。

### 2.5 城市微地形、入渗与排水能力不能被“一个降雨折减系数”替代

基于 CADDIES 的高分辨率城市研究表明，道路、路缘、建筑等微地形会显著改变淹没范围和水深；研究中的常量入渗/排水表示比简单削减降雨更能描述退水过程 [L4]。这说明 DEM 预处理不是附属步骤，而是模型精度的重要组成。

对 RainFall 的含义：

- 建筑应作为抬高或不可通行单元，而不是被 DEM 平滑掉；
- 道路、下穿通道、路缘、堤墙和排水口需保留；
- 入渗与排水应作为显式源汇项；
- DEM 分辨率改变时要重新校准，不能直接沿用参数。

### 2.6 1D 管网—2D 地表耦合是城市应用的关键升级

SWMM 是 EPA 的动态降雨—径流—管渠模拟工具，可描述子汇水区、节点、管道、泵和调蓄设施 [L5]。已有研究将 SWMM 与 WCA2D 耦合：SWMM 负责水文和 1D 管网过程，WCA2D 负责地表二维漫流 [L6]。

建议分两步：

1. MVP 先用“栅格排水能力 + 检查井源汇”简化方案完成闭环；
2. 数据具备后接入 SWMM，按检查井/雨水口双向交换流量。

原因是：没有可信管网拓扑、管径、标高和设施工况时，形式上接入 SWMM 不等于结果可信。

### 2.7 实时预测必须显式处理输入和模型不确定性

雷达定量降水估计（QPE）和短临预报（QPF）存在空间偏差、时序偏差和强对流快速演变问题。雷达降雨同化研究显示，修正降雨输入可以改善水文预报，但模型参数和结构不确定性仍会限制效果 [L7]。顺序数据同化研究使用集合卡尔曼滤波，把水位/流量观测纳入概率淹没图更新，并强调应同时考虑边界、参数和状态不确定性 [L8]。

因此，RainFall 不应只输出一张确定性水深图。建议输出：

- 集合中位数水深；
- $P(h>0.15\ \mathrm{m})$、$P(h>0.30\ \mathrm{m})$ 等超阈概率；
- 到达时间分位数；
- 输入新鲜度、缺测状态和模型置信等级；
- “观测事实”和“模型预测”分层展示。

具体阈值需要根据当地预案、道路和人群脆弱性校准，上述数值仅作为数据结构示例。

### 2.8 GPU 并行有潜力，但必须在目标硬件与目标场景上复测

2025 年的 CA/GPU 水流与污染物输运研究报告了显著加速，并展示了实时模拟潜力 [L9]。这支持采用连续内存栅格、湿单元压缩、双缓冲和 GPU kernel 的工程方向，但单篇论文的网格数、硬件和物理过程不能转化为 RainFall 的性能承诺。

## 3. LLM 与灾害决策研究

### 3.1 适合的角色

ACL 2025 的综述把 LLM 灾害应用按灾害阶段和任务分类，显示其价值主要在多源文本处理、知识检索、报告生成、协作和信息沟通 [L10]。近期系统进一步探索：

- DisasTeller：多视觉语言模型协同完成灾后评估、告警、资源分配和报告，但论文也观察到上游评估错误会传播到下游 [L11]；
- MAESTRO：用角色化多智能体、工具调用和人工监督衔接预测、影响模型与跨部门响应 [L12]；
- DORA：把灾害行动拆成感知、空间关系、救援/疏散、时序推理和多模态报告，并用可回放的工具轨迹评估智能体 [L13]。

这些工作共同支持“LLM 做编排和解释，专业模型做数值真值”的路线。

### 3.2 不应直接授权的角色

DisasterQA 的评测动机本身就是：通用 LLM 的灾害响应知识仍不足以支持无条件决策 [L14]。DORA 还报告了长工具链中的组合脆弱性 [L13]。因此第一版明确禁止：

- LLM 自行生成未由仿真或观测支持的水深、概率和受灾人数；
- LLM 修改正式风险阈值或绕过硬约束；
- LLM 在缺少授权时直接发布政府级预警；
- LLM 以单一自然语言结论覆盖不确定性和模型失效状态；
- LLM 将外部网页或用户文本中的指令当作系统指令执行。

### 3.3 推荐的安全形态

采用“受约束工具调用 + 结构化证据包 + 确定性验证器 + 人工审批”：

1. 智能体只能调用白名单工具；
2. 所有工具输入输出通过 JSON Schema；
3. 风险等级由规则引擎计算，LLM 只能解释；
4. 关键结论必须引用 EvidenceBundle 中的字段；
5. 缺证据、数据过期、仿真失败时必须降级或拒绝；
6. 对外消息经过数值一致性、空间范围、时效、敏感信息和权限检查；
7. 记录模型、提示词、工具调用、版本、人工修改和最终发布内容。

## 4. 预警与推送规范

世界气象组织将端到端预警系统概括为风险知识、监测与预报、传播沟通、准备与响应四个相互关联的部分 [S1]。RainFall 的技术架构应覆盖四部分，而不是只做一张积水图。

公共消息建议参考 Common Alerting Protocol（CAP）1.2 的基本字段，包括：

- 唯一标识与更新/取消关系；
- 事件、紧迫性、严重性、确定性；
- 生效与失效时间；
- 影响区域多边形；
- 简明说明与行动指引；
- 数据和地图资源链接 [S2]。

中国气象局的暴雨蓝、黄、橙、红信号是气象预警信号，主要基于一定时段降雨量及持续状态 [S3]。RainFall 计算的“内涝影响等级”不能冒充气象部门的法定暴雨预警；界面和消息中必须把“气象信号”“模型内涝风险”和“正式发布状态”分开。

## 5. 综合结论

### 推荐技术路线

以“显式质量与惯性的动态波 CA（SWFCA/混合 CA）+ 显式降雨/入渗/排水源汇 + 可选 SWMM 1D 管网 + 集合短临降雨 + 概率影响评估”为数值主线；以完整浅水方程模型、实验室 LSPIV 速度场和独立历史事件逐层验证水深、速度和方向；以“结构化证据驱动的 LLM 多角色编排 + 确定性硬门 + 人工发布审批”为决策主线。

### 主要研究空白与项目机会

1. **快且可信的在线闭环**：许多论文只验证求解器或单个决策环节，缺少从实时输入到发布回执的全链路验证。
2. **概率风险而非单次水深图**：集合降雨、状态更新和模型结构误差常未被统一传给决策层。
3. **LLM 证据约束**：灾害智能体容易在长工具链中累积错误，需要可回放证据、硬门和拒答机制。
4. **面向对象的影响评估**：道路、地下空间、医院、学校、变电设施和脆弱人群应采用不同阈值与行动模板。
5. **正式预警治理**：内部提示、专家建议和公开预警必须有不同权限、模板与审计要求。
